# 관리자 계정 복구 절차 (초기 버전)

이 문서는 **관리자 비밀번호를 잊었을 때**의 운영자 복구 절차를 정리한다.

## 먼저 알아야 할 것

- 관리자 비밀번호는 **scrypt 해시로만** 저장된다. 원래 비밀번호를 꺼내 볼 방법은 없다(복호화 불가).
- **일반 닉네임 로그인으로는 관리자 계정에 접속할 수 없다.** 세션 쿠키 이름과 종류(`sessions.kind`)가
  분리돼 있고, 서버가 `/api/auth/login`에서 관리자 계정을 명시적으로 거부한다. 즉 비밀번호 분실 시
  "일반 로그인으로 우회"하는 경로는 **의도적으로 존재하지 않는다**.
- 관리자 계정은 DB에 **최대 1개**만 존재할 수 있다(`ux_users_single_admin` 부분 유니크 인덱스).
  따라서 "새 관리자를 하나 더 만들기"로는 복구할 수 없고, 아래처럼 기존 관리자 행을 먼저 정리해야 한다.
- 이 절차는 **DB에 직접 접근할 수 있는 운영자**만 수행할 수 있다. 앱 화면만으로는 불가능하다(의도된 설계).

## 복구 절차 (DB 직접 접근)

DB 콘솔(Vercel Storage → Postgres의 Query 탭, 또는 psql)에서 진행한다.

### 방법 A — 관리자 계정을 지우고 최초 가입을 다시 여는 방법 (권장)

관리자 계정은 플래너 데이터를 거의 갖지 않으므로 보통 이 방법이 가장 간단하다.

```sql
-- 1) 현재 관리자 확인 (비밀번호 해시는 조회하지 않는다)
SELECT id, nickname, created_at FROM users WHERE role = 'admin';

-- 2) 관리자 세션 정리
DELETE FROM sessions WHERE user_id = '<위에서 확인한 id>';

-- 3) 관리자 프로필/계정 삭제 (FK 때문에 profiles를 먼저 지운다)
DELETE FROM profiles WHERE user_id = '<id>';
DELETE FROM users    WHERE id = '<id>' AND role = 'admin';
```

삭제 후에는 `ADMIN_INVITE_CODE`를 **새 값으로 바꾸고 재배포**한 뒤, 앱의
`☰ → 관리자 로그인 → 최초 관리자 가입`에서 다시 가입한다(관리자가 0명이므로 가입 경로가 자동으로 열린다).

> 주의: 일반 사용자(`role='user'`)의 행은 절대 지우지 않는다. 위 쿼리에는 모두 `role='admin'` 조건이 들어 있다.

### 방법 B — 닉네임을 유지한 채 비밀번호만 교체

관리자 닉네임/가입일을 유지해야 한다면, 새 비밀번호 해시를 만들어 직접 갱신한다.

```bash
# 프로젝트 루트에서 실행. 새 비밀번호를 인자로 넘기면 해시 문자열만 출력된다.
node -e "require('./lib/password').hashPassword(process.argv[1]).then(console.log)" '새-비밀번호'
```

```sql
UPDATE users SET password_hash = '<위에서 출력된 scrypt$... 문자열>' WHERE role = 'admin';
DELETE FROM sessions WHERE user_id = (SELECT id FROM users WHERE role='admin'); -- 기존 세션 무효화
```

- 출력된 해시 문자열과 새 비밀번호는 로그·이슈·채팅에 남기지 않는다.
- 해시 생성은 로컬에서만 수행하고, 터미널 히스토리에 비밀번호가 남았다면 지운다.

## 복구 후 점검

1. `☰ → 관리자 로그인`으로 새 비밀번호 로그인이 되는지 확인한다.
2. 관리자 페이지 → **이력** 탭에서 복구 전후의 작업 기록이 남아 있는지 확인한다
   (이력과 백업은 계정을 지워도 삭제되지 않는다).
3. `ADMIN_INVITE_CODE`를 교체했다면, 더 이상 쓰지 않는 예전 값이 어디에도 남아 있지 않은지 확인한다.

## 이번 버전에서 지원하지 않는 것

- 앱 화면을 통한 비밀번호 재설정(이메일/문자 인증 경로가 없다)
- 관리자 추가 초대 · 권한 변경 · 다중 관리자
- 삭제된 계정의 재생성(백업 JSON으로 **기존 계정에 데이터 복원**만 가능)
